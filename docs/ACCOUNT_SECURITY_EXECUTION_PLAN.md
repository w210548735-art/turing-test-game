# 账户安全执行计划

## 当前优先级

### P0：Demo 必须完成

- [x] 开放注册、邮箱验证、登录、注销与密码恢复；
- [x] “重新发送验证邮件”协议、HTTP 路由和前端入口；
- [x] 统一公共响应，禁止通过响应内容判断账户是否存在或是否已激活；
- [x] 验证 Token 原子轮换，重发后旧链接立即失效；
- [x] 邮件发送复合限流；
- [x] SMTP 失败结构化告警、服务内状态快照与外部告警回调；
- [x] SMTP 失败仍返回统一 `202`，告警回调失败不影响公共接口；
- [x] 协议、服务、PostgreSQL Repository、HTTP 和前端自动化测试；
- [x] 浏览器交互验收与经授权的 QQ SMTP 单封真实投递测试。

### P1：Beta 前完善

- [x] PostgreSQL 中 Token 轮换事务化；
- [x] 服务内监控输出连续失败、累计失败和最近失败时间，公共健康接口不暴露
  投递计数；
- [x] 告警数据最小化，不记录邮箱、Token、密码、授权码或错误正文；
- [ ] 在目标部署环境把 `SMTP_DELIVERY_FAILED` 接入已有日志告警平台，并完成
  一次不使用真实凭据的演练；
- [ ] 为邮件域名配置并验证 SPF、DKIM、DMARC，持续观察退信与垃圾邮件率。

### P2：Demo 可暂缓

- [ ] 引入持久化邮件 Outbox、后台重试和死信队列；
- [ ] 建立投递供应商切换与自动故障转移；
- [ ] 增加按邮件类型、供应商响应和时间窗口聚合的运营看板。

## 回归判定

发布前必须同时满足：

1. 类型检查、全量自动化测试与生产构建全部通过；
2. 重发接口对待验证、已激活和不存在邮箱返回相同状态码与响应；
3. 重发后旧 Token 无效，新 Token 可完成邮箱验证；
4. 超过邮件发送限额时返回 `429`；
5. 模拟 SMTP 失败时公共接口仍返回 `202`，告警只包含安全字段；
6. 登录页可进入重发页面，且页面不要求输入密码。
